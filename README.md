## Maker versus taker: the part many fee comparisons miss

The maker-taker distinction affects the final result more than many referral-code pages explain.

A **taker** removes liquidity from the order book by matching against orders already available. Market orders usually fall into this category.

A **maker** adds liquidity by placing an order that remains on the order book until another trader matches it. A limit order can qualify as maker, but only if it does not immediately match an existing order.

That means a limit order is not automatically cheaper. If the limit price crosses the current order book and executes immediately, OKX may classify it as taker execution. The actual fill behavior controls the fee.

For active traders, the sensible workflow is:

1. Open the exact trading pair.
2. Check the maker and taker rates shown for your account.
3. Decide whether speed or execution-cost control matters more.
4. Estimate the fee using the expected filled amount.
5. Check the completed order details after execution.

A referral discount can reduce either fee category if the program terms cover that product, but it does not change the difference between maker and taker execution.
